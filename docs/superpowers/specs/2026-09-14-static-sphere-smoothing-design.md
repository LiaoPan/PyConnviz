# Static Surface Sphere Smoothing Design

## Problem

The supplementary Matplotlib three-view and native Nilearn six-view figures now
use physical 3D node spheres, but each sphere is tessellated with only eight
latitude steps and twelve longitude steps. That produces 168 planar triangles
per node. Matplotlib shades those planar faces individually, so large nodes show
both a polygonal silhouette and a visible checkerboard of lighting facets.

## Scope

This correction applies only to the shared static node-sphere geometry used by
the Matplotlib and native Nilearn surface renderers. It must not change node
coordinates, physical diameters, node colours, edge tubes, direction cones,
cortical opacity, camera views, prepared edges, or the interactive Plotly
renderer.

## Considered approaches

1. Increase the UV-sphere resolution to 24 latitude steps and 36 longitude
   steps. This produces 1,656 triangular faces per sphere and preserves true 3D
   size, lighting, occlusion, and deterministic export. A real-MSDL visual
   check removed the coarse facets, while the 200-node benchmark completed in
   18.07 seconds. This is the selected approach.
2. Use a smaller 20-by-32 mesh. It is cheaper, but an isolated enlarged render
   still shows visible latitude bands, so it does not fully resolve the reported
   defect.
3. Overlay a 2D circular marker or disable shading. Either option can conceal
   faceting, but it removes physical 3D depth or the intended spherical material
   cue and therefore violates the ball-and-stick requirement.

A 32-by-48 mesh was also measured. It produced the smoothest enlarged isolated
sphere, but took 29.23 seconds in the 200-node benchmark and failed the existing
20-second performance gate, so it was rejected.

## Design

The shared Matplotlib ball-and-stick adapter will use a fixed 24-by-36 UV sphere
for every static node. Batching remains unchanged: every panel contains one
node `Poly3DCollection`, and its triangles are still generated by the common,
validated `sphere_mesh` primitive. Edge and direction mesh resolutions remain
unchanged to bound the performance impact.

The static geometry audit will record the number of sphere triangles per node.
The strict acceptance checker will require at least 1,656 triangles per sphere,
so a future change cannot silently restore a visibly low-poly node mesh. Unit
tests will assert the exact current topology and confirm that centres, colours,
diameters, depth cueing, and batching remain intact.

## Verification

Verification comprises:

- a red/green unit test for the 24-by-36 sphere topology;
- an acceptance-checker regression test that rejects low-resolution spheres;
- focused Matplotlib and native Nilearn surface tests;
- regenerated deterministic acceptance artifacts and real MSDL gallery images;
- original-resolution visual inspection of both supplementary figures;
- the acceptance performance check, full test suite, package build, and package
  metadata validation.

Success means the node silhouettes and lighting gradients appear smooth at the
published image size, the static renderers retain true 3D ball-and-stick
geometry, and all automated correctness and performance gates pass.
